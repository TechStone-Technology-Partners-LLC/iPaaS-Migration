MigrAIte Target Architecture

The proposed workflow for webMethods → Workato migrations: verification at every stage, format knowledge moved out of the AI agent's hands, and two interchangeable build paths — our own builder library, or Workato AIRO.

Three design principles drive everything below:

  1. Every stage's output is checked against an artifact from the stage before — so every failure has an address.
  2. The agent only ever touches intent — analysis, tests, definition — while format, coverage, and verification live in deterministic code.
  3. The recipe JSON is a build artifact, never a source file — all fixes happen upstream and recompile down.

Skills as the learning ledger Each build path carries its own skill file, loaded into the agent's context at build time and updated from the report at the end of every run: a pitfall the lint or pull-back diff caught goes into build-with-library; a quirk in how AIRO interpreted a blueprint goes into drive-AIRO. This formalizes how the current 15 push rules were actually born — push failures hand-transcribed into the skill doc — into a closing loop the workflow performs on itself. Two disciplines keep it healthy: entries are curated, not appended raw (dedup against existing entries; a human approves skill edits like any other artifact), and anything that can become a library default or lint check should graduate out of the skill into code — the skill holds only what still requires judgment.
Why the verification tail never changes Both builders are LLMs — ours and Workato's. The tail (tests, pull-back diff, report) was designed to trust no builder, so swapping the builder swaps nothing downstream. The open question between the paths is empirical, not architectural: can AIRO follow a step-level blueprint precisely and deterministically? A one-day spike — feed it a known package's §8 step tree + §5 mappings, pull the result, diff against §8 — answers it before any library-building investment.
What this retires from the current workflow The sequential-prompts file (WMToWorkato.md) disappears — it was scaffolding for hand-assembling brittle JSON step by step; the definition file (or AIRO blueprint) replaces it, with traceability moving into inline comments citing analysis rows. Per-script helper code disappears into the central library. The hardcoded per-recipe assertions generalize into the tree-walking lint. The manual "open the GUI and look for grey boxes" check becomes the pull-back diff. The analysis, the human gate, and the canonical-specimen discipline all survive unchanged.
