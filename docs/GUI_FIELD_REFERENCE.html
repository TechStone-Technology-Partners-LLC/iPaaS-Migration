MigrAIte GUI Field Reference

What every field, button, and toggle in the MigrAIte Streamlit app does, grouped by the screen it appears on. Written against the current build of app.py — if a label or default moves, this is the file to update.

Global controls

Two controls sit above the three mode tabs and apply no matter which mode you're in.

ControlTypeDescription
ThemeDark / Light toggleSwitches the whole app's palette. Dark is the default. Every color in the UI routes through one shared token set, so this is a full re-theme, not a partial one — including the platform tiles, inputs, badges, and the terminal log panel (which stays black in both themes, like a code editor's console).
Mode selector3-way segmented controlMigrate Package runs the full pull → analyze → enrich → document → generate pipeline. Generate from Analysis skips straight to recipe generation from an existing analysis document. Push Recipe JSON skips generation entirely and just pushes an already-built recipe file. Switching modes resets the fields below it.

Migrate Package Mode 1

The default mode: a full pipeline run from a source platform to a target platform. The screen is built as two side-by-side cards — Source Platform on the left, Target Platform on the right — followed by a shared Migration Options bar and a Run button.

Migration Options

A shared options bar below both platform cards, applying to the run regardless of source/target choice.

FieldTypeDefaultDescription
Package / project name ✱text(derived if blank)Used to name the spec file and destination folder. Defaults to the zip filename, directory name, or live-pull folder/integration name if left blank.
Destination folder / projecttextMIG_<project>The container the migrated asset(s) get pushed into on the target platform.
Markdown dir for doc appendixtexte.g. WebMethods/MD/Optional — attaches markdown files from this directory as an appendix to the generated Word design document.
Dry runcheckboxoffGenerate artifacts without pushing to the target. Note: this does not apply to AIRO builds below — see its own warning.
Skip analyzecheckboxoffRe-use an existing spec already in migration-specs/ instead of re-analyzing the source.
Skip enrichcheckboxoffSkip the AI enrichment pass. Faster, but lower-quality output for nested/complex service logic.
Skip documentcheckboxonSkip Word design-document generation. On by default — that step makes no LLM calls itself (it's local .docx assembly from the already-generated spec), but it's the phase you're least likely to need on every run. Uncheck to also get the branded .docx this run.
Build via AIRO (live-validated)checkboxoffOnly shown when Target is Workato. Resolves and validates every connector/action live against Workato's real schema via the AIRO MCP recipe builder, instead of the static generator's blind JSON assembly (which falls back to "Select an app and action" placeholders it can't map). Slower and uses LLM tokens. Auth rides on Claude Code's own login, not the Workato API token field above.
AIRO + Dry run AIRO creates each recipe live in Workato as it builds, regardless of the Dry run checkbox — Dry run only skips the final push of its steps. It is not a no-side-effects mode when AIRO is enabled.

Run & Progress

Clicking Run Migration resolves the source into exactly one of: a prepared local directory, or a live-pull reference (credentials riding along separately), then launches migrate.py as a subprocess and streams its output live.

ElementDescription
Step trackerFive pipeline phases shown as connected cards: Pull (fetch source files) → Analyze (parse flows & services) → Enrich (AI deep enrichment) → Document (design document) → Generate (push to target). Each lights up as the subprocess emits its matching [PHASE] marker, and is marked done once the next phase begins.
Live logA terminal-styled panel showing the last 30 lines of subprocess output, updating as the run progresses.
Status badge"Migration completed successfully" or "Migration failed (exit N)" once the subprocess exits.
Full migration logA collapsible expander with the complete captured output — expanded automatically on failure.
